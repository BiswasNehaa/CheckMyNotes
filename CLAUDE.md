# Project Instructions

## Context
This is a student assignment with a 3-day deadline.
I need to understand the code because I will be asked questions about my implementation.

## Development Rules
- Keep everything simple and beginner-friendly.
- Prioritize a working MVP over advanced architecture.
- Do not over-engineer.
- Prefer readable code over complex solutions.
- Work on ONE feature or function at a time.
- Never implement multiple features unless explicitly asked.
- Do not rewrite unrelated working code.
- Reuse existing code where possible.
- Make the minimum changes necessary.

## Before Coding
Before changing code:
1. Read the relevant existing files.
2. Briefly tell me what you found.
3. Tell me exactly what you plan to change.
4. Work only on the task I requested.

## After Coding
After completing a task, give me ONLY:

### Done
One sentence describing what was completed.

### What Changed
- Short bullet points

### Why
- Simple explanation of why each change was needed

### How It Works
- 3-5 simple bullets explaining the flow

### Files Changed
- File name: purpose

## Git Checkpoints
After a meaningful feature is completed and tested:
- Tell me it is a good Git checkpoint.
- Suggest one short commit message.
- Remind me to commit and push.
- Do NOT automatically commit or push.

## Response Style
- Keep responses short and concise.
- Do not give long explanations unless I ask.
- Do not explain unrelated code.
- Focus on helping me understand what we are currently building.
